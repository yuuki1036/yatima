# 共通仕様（common_spec.md）

yatima の全フィーチャーが従う共通の前提・閾値・エラー仕様。
個別 `spec.md` はここを参照する。

---

## Background（共通前提）

yatima は **自分専用** のアプリケーションである。全 Scenario が暗黙的に持つ前提:

```gherkin
Given アプリは単一利用者（オーナー本人）のために動作している
And 認証は行わない（Phase 1 時点。将来必要になれば別 epic で追加）
And データベース（Supabase/Postgres）に接続できている
```

> Phase 1 ではマルチユーザー・権限・認証はスコープ外。個別 spec.md でこれを上書きする場合は明示的に書く。

## デフォルトエラーメッセージ

| 状態 | エラーID | メッセージ | 対応 |
|------|---------|-----------|------|
| 不正なフィード URL | ERR-FEED-001 | "有効な RSS/Atom フィードの URL を入力してください" | 入力欄横にエラー表示 |
| 重複フィード登録 | ERR-FEED-002 | "このフィードは既に登録されています" | 既存フィードへ誘導 |
| フィード取得失敗（ネットワーク/タイムアウト） | ERR-FETCH-001 | （UI 非表示・収集ログに記録） | 次回収集で自動リトライ |
| フィード取得失敗（4xx/5xx） | ERR-FETCH-002 | （UI 非表示・収集ログに記録、連続失敗時にフィードへ警告フラグ） | 手動でフィード確認を促す |
| フィードのパース失敗（不正 XML） | ERR-PARSE-001 | （UI 非表示・収集ログに記録、当該フィードのみスキップ） | 他フィードの収集は継続 |
| DB 接続エラー | ERR-SYS-001 | "データの読み込みに失敗しました。時間をおいて再試行してください" | reload 導線 |

> 収集（バッチ処理）系のエラーは UI に出さずログに記録し、収集ジョブ全体を止めない方針（フィード単位で隔離）。

## 共通閾値

| 項目 | 値 | 根拠 |
|------|-----|------|
| 収集間隔 | 1 時間ごと | all_spec.md 参照 |
| 一覧ページネーション | 50 件 | all_spec.md 参照 |
| フィード取得タイムアウト | 10 秒 | 遅延フィードで収集全体を詰まらせない |
| 収集の同時取得数 | 5 並列 | 外部サーバへの負荷とジョブ時間のバランス |

## 設計判断

### 収集エラーを UI に出さずログに集約する理由

- 収集はバックグラウンドの cron ジョブであり、利用者がその場にいない
- フィード単位の失敗で収集ジョブ全体を止めると、健全なフィードの新着も取れなくなる
- フィード単位でエラーを隔離し、連続失敗時のみフィードに警告フラグを立てて利用者に気づかせる

### Phase 1 で認証を持たない理由

- 自分専用・ローカル/自分だけのクラウドが前提（project-requirements）
- 認証は本質的価値（情報収集）に寄与しないため、必要になった時点で別 epic 化する
