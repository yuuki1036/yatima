# Epic: RSSフィードの自動収集と閲覧（Phase 1 土台）

## User Story

Userは、**自分専用RSSリーダーを使う開発者本人** として、**登録した複数のRSS/Atomフィードを定期的に自動収集して記事をDBに保存し、フィード横断の一覧で新着順に読みながら既読/未読を管理し、フィードを登録・削除** したい。

## Why（動機）

AI機能（要約・ランキング・情報源発見・RAG）を載せる前の土台として、まず「動くRSSリーダー」を成立させる。後続フェーズがそのまま乗る、素直で拡張しやすいデータモデル（feeds / articles）と収集パイプライン（収集→パース→保存）を確立することが目的。ここが全フェーズの基盤になる。

## What（成果物の輪郭）

このエピックが完了した時、以下が達成されている:

- [ ] 複数のフィードを登録・削除できる（最小UI）
- [ ] cron（GitHub Actions → `/api/cron/fetch`）が定期的に全フィードを収集し、新着記事を保存する
- [ ] 収集は重複記事を二重保存せず、一部フィードの失敗が他フィードの収集を妨げない
- [ ] フィード横断の記事一覧が新着順で表示される
- [ ] 記事の既読/未読を管理でき、未読フィルタが機能する

## Acceptance Criteria（受入条件）

以下の Scenario が `spec.md` で定義され、全て pass する:

- [ ] AC-1: 有効なフィードを登録できる → `spec.md:#scenario-1`
- [ ] AC-2: 不正なURL・重複URLの登録は拒否される → `spec.md:#scenario-2`
- [ ] AC-3: 収集ジョブが新着記事を保存する → `spec.md:#scenario-3`
- [ ] AC-4: 重複記事は二重保存されない（guid優先→url一意） → `spec.md:#scenario-4`
- [ ] AC-5: 一部フィードの取得/パース失敗が他フィードの収集を妨げない → `spec.md:#scenario-5`
- [ ] AC-6: 記事一覧がフィード横断・新着順で表示される → `spec.md:#scenario-6`
- [ ] AC-7: 記事を既読にでき、未読フィルタに反映される → `spec.md:#scenario-7`
- [ ] AC-8: フィードを削除できる → `spec.md:#scenario-8`

> AC は `spec.md` の Scenario と双方向リンクする。

## スコープ外

このエピックで **やらないこと**（後続フェーズ / 別 epic 候補）:

- AI 機能すべて（要約=Phase2 / ランキング=Phase3 / 情報源の自動発見=Phase4 / 横断Q&A・レポート=Phase5）
- pgvector / embedding 生成
- RSS 非公開サイト対応（RSSHub）、arXiv 連携
- 認証・マルチユーザー
- 記事本文のフルスクレイピング（RSS提供の content/summary のみ保存）
- 凝ったデザイン・モバイル最適化
